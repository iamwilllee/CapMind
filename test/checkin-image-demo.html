图片按钮与画布按钮

验证 DOM 无法直接读到文案时的识别与执行 · 不需要登录 · 不发任何网络请求

用例 1 · 按钮内嵌图片，有 alt

结构：<button><img alt="签到领额度"></button>
textContent 为空，文案只存在于 img 的 alt 上。
期望：textHint = 「签到领额度」，textHintSource = attr，可正常校验。

用例 2 · 按钮内嵌图片，只有文件名有语义

结构：<button><img src="btn_checkin_claim@2x.png"></button>
无 alt、无 title、无 aria-label，只能从 src 文件名推断。
期望：textHint = 「btn checkin claim」，textHintSource = attr。

用例 3 · 纯 CSS 背景图，无任何文案来源

结构：<div role="button">，文字画在背景图里，元素本身没有文字、没有 alt、没有可读文件名。
这是唯一必须靠 OCR 才能读出文字的形态。
期望：能选中按钮、textHintSource = none，执行时只校验元素存在，不应误判「文案不匹配」。

用例 4 · canvas 自绘按钮

结构：<canvas>，文字用 fillText 画上去。
没有语义标签、textContent 为空，elementsInRect 挑不出来，只能靠中心点兜底。
期望：走 elementsFromPoint 兜底拿到 canvas 节点，selector 可用，textHintSource = none。

用例 5 · 文字包在 span 里

结构：<button><span>签到领额度</span></button>
React/Vue 组件的典型输出。直接文本节点为空，文字在后代 span 里。
期望：textHint = 「签到领额度」，textHintSource = text（不能退化成 none）。
每个用例独立。框选后点「识别这块 →」，看侧栏「按钮选择器」「文案校验」两行是否符合上面的期望。
「试跑一次」会真的点一次，成功后状态变绿。刷新页面可重置。
